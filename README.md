# Семейный Фиббаж

Браузерная семейная игра в стиле Fibbage/Drawful. Игроки придумывают вопросы, отвечают на чужие, сочиняют ложные ответы и стараются угадать правильный.

**Все данные хранятся в памяти сервера. При перезапуске сервера вся игра сбрасывается.**

---

## Установка и запуск

```bash
npm install
PORT=3000 npm start
```

Или на EC2:

```bash
PORT=3000 npm start &
```

Разработка (с автоперезагрузкой):

```bash
npm run dev
```

## Доступ

| Кто               | URL                              |
|-------------------|----------------------------------|
| Телевизор / хост  | `http://<публичный-IP>:3000/host` |
| Игроки (телефоны) | `http://<публичный-IP>:3000/`    |

Откройте хост-страницу на телевизоре — там отображается URL и (если есть `public/qr.png`) QR-код для быстрого подключения.

---

## QR-код (необязательно)

Поместите файл `public/qr.png` (QR-код, ведущий на `http://<IP>:3000/`), и хост-страница автоматически его отобразит.

## Правила игры

1. **4–10 игроков** присоединяются в зале ожидания.
2. Любой игрок нажимает **«Начать игру»** (минимум 4 человека).
3. **3 раунда**, в каждом:
   - Все придумывают вопрос.
   - Каждому достаётся чужой вопрос — нужно честно ответить.
   - Затем остальные сочиняют **ложные ответы** на этот вопрос.
   - Все голосуют, какой ответ настоящий (нельзя голосовать за свой ложный).
   - **Раскрытие**: ложные ответы с голосами, затем правильный.
4. После 3 раундов — финальный счёт.

### Очки

| Событие | Очки |
|---------|------|
| Угадал правильный ответ | +1000 |
| Ввёл игроков в заблуждение (за каждого) | +500 |
| Никто не угадал правильный ответ | +1500 (автору) |

## Сценарии ручного тестирования

1. Запустить приложение, открыть `/host` на одной вкладке и 4 вкладки `/` на других.
2. Войти с 4 уникальными именами — убедиться, что все появились на хост-странице.
3. Попробовать войти с уже существующим именем — убедиться, что пришла ошибка «Имя уже занято».
4. Нажать «Начать игру» при 3 игроках — получить ошибку о минимуме 4.
5. Добавить 4-го игрока, нажать «Начать игру» — перейти к фазе написания вопросов.
6. Каждый игрок отправляет вопрос — убедиться, что никто не получил свой собственный вопрос.
7. Каждый отвечает на свой назначенный вопрос.
8. Во время фазы ложных ответов: игрок с настоящим ответом не видит поле ввода и получает ошибку если пытается отправить.
9. Попробовать отправить ложный ответ, совпадающий с настоящим или уже существующим ложным — получить ошибку «Такой ответ уже есть».
10. Во время голосования: авторы ответов не подписаны — убедиться в этом на экране.
11. Игрок с настоящим ответом не может голосовать. Кнопка его собственного ложного ответа заблокирована у других.
12. После всех голосов: раскрытие происходит автоматически, ~2 секунды между пунктами.
13. Проверить начисление очков:
    - Угадавший получает +1000.
    - Автор ложного ответа получает +500 за каждого обманутого.
    - Если никто не угадал — автор настоящего ответа получает +1500.
14. Пройти все вопросы раунда → кнопка «Следующий раунд». После 3 раундов → финал.
15. Сброс в любой фазе: появляется диалог «Вы уверены?», после подтверждения всё очищается.
16. После сброса и перезагрузки страницы: поле имени предзаполнено из localStorage.

## Технические детали

- **Node.js + Express + Socket.IO** — без базы данных, без сборки, без Docker.
- Весь игровой стейт — в памяти одного процесса.
- Сессии игроков — UUID в cookie + localStorage (для восстановления соединения).
- При перезапуске сервера стейт теряется; игроки видят форму входа с предзаполненным именем.
